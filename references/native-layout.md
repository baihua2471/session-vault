# Native adapters and limits

- Codex: session and archived-session JSONL plus indexed `threads` rows from `state_*.sqlite`, `projects`, `thread_sections`. The archive display label uses `name`, then `title`, `preview`, and `first_user_message`, with the ID as a final fallback; `title_source` records which field supplied it. Restore preserves the original `title`. If `name` is empty, it fills `name` from the archived display label; an optional name prefix is applied to `name` only. Titles, pinned state, ordering, group IDs, parent-thread IDs and original cwd survive in manifests. Raw unindexed rollouts are backed up but may need native discovery/reindexing on restore. Native project metadata is preserved as stored; JSON strings embedded in metadata and arbitrary tool arguments/transcript text are not globally rewritten. Desktop global-state layouts, worktree attachments and server/account-side grouping are not fully reconstructed. Restore target should use matching Codex version/schema. Profile migration uses a whitelist for memories, rules, skills, prompts, `AGENTS.md` and `config.toml`; a file matching credential rules is omitted. Logs, caches and worktree code are not copied.
- Claude Code: `projects/*/*.jsonl`, plus the corresponding session's subagent JSONL. Original encoded project grouping, cwd, summaries/custom titles and session IDs retained. Directory remapping rebuilds project folder names with Claude's path encoding. Optional title/search indexes are not required for transcript storage and are not imported; application versions may rebuild them. Profile migration includes whitelisted rules, skills, commands, agents, and project memory Markdown; settings files are screened for credential-like values. Arbitrary desktop Claude chat databases are out of scope.
- Hermes: root and named-profile `state.db` via SQLite online snapshot. The archive contains a full, hash-verified SQLite snapshot and per-session native `sessions` rows, `messages` and regular tables with a `session_id` column; FTS caches excluded from row-level import. Parent IDs are preserved. Target must initialize the same profile/schema. Stop Hermes gateway as well as TUI/Desktop before apply. Message integer-ID conflicts or unique-title conflicts abort instead of overwriting; do not use this adapter to merge divergent histories of the same session. Cross-session normalization/reference tables without `session_id` are not covered; for a new Hermes schema inspect its foreign keys and use Hermes's native JSON export/import if required. Hermes is fixture-tested, not live-tested on this Mac. Hermes memory and non-sensitive config files are whitelisted separately.
- Pi: `sessions/<encoded-cwd>/*.jsonl`; validates each JSONL row and the native `session` header, derives the label from `session_info.name` then the first user message, and rebuilds Pi's documented encoded-cwd folder when a workspace is remapped. `PI_CODING_AGENT_DIR` is respected. A custom `PI_CODING_AGENT_SESSION_DIR` outside `<agent-dir>/sessions` is detected and blocks snapshot promotion rather than being silently skipped. Profile whitelist includes global instructions, settings, keybindings, skills, prompts, extensions and themes; `auth.json`, MCP config and model credentials are excluded. Pi 1.5.0 is installed and its CLI version check passed; fixture restore passed, but a real session has not yet been resumed.
- CodeBuddy CLI: `projects/<opaque-project-key>/*.jsonl`; validates transcript JSONL, derives a label from session metadata or the first user message, preserves the project key and rewrites recognized cwd fields. `CODEBUDDY_CONFIG_DIR` is respected. Profile whitelist includes `CODEBUDDY.md`, rules, agents, skills, commands, global memories, and screened settings. MCP config is excluded. The opaque project key and undocumented `history.jsonl` format prevent guaranteed project-picker reindexing after a workspace remap; the documented `--resume <session-id>` path is the intended continuity check. File/fixture import is tested; native CLI resume is not.
- CodeBuddy CN IDE: use the IDE's own JSON/ZIP conversation exports, not a copy of its application database. `--codebuddy-cn-exports` scans `.json` files and batch-export `.zip` files, validates the installed 4.12.2 extension's `codebuddy.conversation` schema version 1 and 20 MiB per-conversation limit, then stores each conversation as a readable, selectable session. Restore writes a native ZIP import bundle to the selected destination folder; import it from CodeBuddy CN's History view. Scheduled runs only back up exports already present in that folder; no supported background export command was found. App settings, login state and profile memories are not copied. Fixture validation and ZIP generation passed; the installed app was signed out during verification, so native import and conversation continuation remain unverified. [IDE release notes](https://www.codebuddy.cn/docs/ide/release-notes/release-notes), [History guide](https://www.codebuddy.cn/docs/ide/User-guide/History).

## Additional agents: feasibility and limits

The implementation imports sessions for Codex, Claude Code, Hermes, Pi, CodeBuddy CLI, and CodeBuddy CN IDE exports. It also backs up shared `~/.agents/skills` and ZCode global profile files; ZCode session history is excluded. The following rows record the remaining recovery boundaries and candidates.

| Agent | Evidence and feasibility | Safe recovery boundary |
|---|---|---|
| Pi | Implemented: the official CLI stores JSONL sessions by encoded working directory and supports path-based resume. The adapter rewrites the header cwd and regenerates the encoded directory on remap. [Pi session docs](https://github.com/pi-packages/earendil-works-pi/blob/main/packages/coding-agent/docs/sessions.md), [Pi directory encoding](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/session-manager.ts) | Fixture-verified; Pi 1.5.0 installed and CLI version checked, but no real session resume check has been run. Project-local `.pi` configuration remains part of the project and is not gathered by the global-home backup. |
| CodeBuddy Code CLI | Implemented: the official docs place transcripts at `~/.codebuddy/projects/{id}/{sessionId}.jsonl` and document `--resume <session-id>`. The adapter retains the opaque project key, validates transcripts, and rewrites cwd fields. [CodeBuddy directory guide](https://www.codebuddy.ai/docs/cli/codebuddy-dir), [CLI resume reference](https://www.codebuddy.ai/docs/cli/cli-reference) | Fixture-verified; no live CodeBuddy resume check. The opaque project key is retained and `history.jsonl` is not backed up or merged, so the per-project picker may not reindex a remapped session. Explicit `--resume <session-id>` is the intended check. Project-local `.codebuddy` config remains in the project. |
| CodeBuddy CN IDE | Implemented through official JSON/ZIP exports validated against the installed extension's schema `codebuddy.conversation` v1; restore builds an IDE-importable ZIP under the user-selected import folder. [IDE release notes](https://www.codebuddy.cn/docs/ide/release-notes/release-notes), [History guide](https://www.codebuddy.cn/docs/ide/User-guide/History) | Fixture-verified. The app is signed out on this Mac, so its native History import has not been run. App settings and global memory/rules are not captured because their local storage path is undocumented and the application database includes credential storage. |
| Qoder CLI | The CLI documents `/export`, `/resume`, and session IDs. Its Agent SDK offers external session storage that mirrors opaque entries and can resume by ID across hosts. [Qoder CLI commands](https://docs.qoder.com/cli/commands), [Qoder external session storage](https://docs.qoder.com/cli/sdk/session-storage) | Feasible for a Qoder SDK adapter or exported conversation archive. A filesystem-only importer for existing desktop/CLI stores is not justified by the public docs; the SDK store is the supported cross-host route. |
| WorkBuddy | The app exposes its system cache directory and task retention settings in the UI; its docs do not specify a stable on-disk session schema or native import API. [WorkBuddy system settings](https://www.workbuddy.ai/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/System-Settings) | Deferred per user instruction. No native session adapter implemented. |
| TRAE (the user's “TREA”) | TRAE's official community response says conversation history is linked to an internal workspace ID and there is no manual rebind function when a restored project gets a new ID. [TRAE history recovery response](https://forum.trae.cn/t/topic/46063/2) | Deferred per user instruction. No native session adapter implemented. |
| Z.ai ZCode | Implemented profile-only backup for `~/.zcode/AGENTS.md`, `cli/config.json`, `v2/config.json`, plus global agents, skills and commands. Files with credential-like values are excluded; `v2/credentials.json` and `v2/telemetry-state.json` are explicitly omitted. [ZCode migration FAQ](https://zcode.z.ai/en/docs/qa) | Fixture-tested profile collection and credential/device-identity exclusions. Session history is not backed up, per vendor guidance. |

Remaining candidate: investigate a Qoder SDK-backed adapter. Its documented `/export` command only exports the current session, while the SDK external store is an application integration and does not establish a safe importer for all existing CLI sessions. WorkBuddy and TRAE remain deferred per user instruction. Before calling Pi or CodeBuddy recovery fully verified on a user's machine, open one restored session in the native application and confirm the expected transcript/context.

The tree groups by provider → native group/profile → original cwd → title/ID. Parent IDs show fork lineage even when the parent is missing; it does not fabricate missing parents. For fully restoring Codex sidebar sections from a different account or unsupported version, use this tree as the source of truth and re-create any unsupported UI grouping manually.

Cloud sync completion: this skill does not inspect Nutstore, iCloud, Huawei Cloud or Weiyun's private client state. The receiving-computer `verify --ack` receipt is a format-neutral proof that the referenced data arrived and passed local checks. Older snapshots are removed only after the receipt returns through the user's sync folder; without it, they remain.
